# Python の処理

`run_check.py` は、設定を読み込み、サンプル画面から勤怠データを取得してチェックし、HTML レポートを作成します。

## ファイルと定数

- `ROOT`：スクリプトがあるフォルダー。実行時のカレントディレクトリに依存せず、他のパスを決めるために使います。
- `SITE`：検証用の HTML を置いた `site` フォルダー。
- `CONFIG`：取得先やチェックルールを指定する `config/check.json`。
- `OUTPUT`：生成したレポートを保存する `output` フォルダー。

## `load_config()`

引数はありません。`CONFIG` の JSON を UTF-8 で読み込み、設定を辞書として返します。

`site_url`、`frames`、`table`、`rows`、`columns`、`rules` の存在を確認し、欠けていれば項目名を含む `ValueError` を発生させます。値の型やセレクターの妥当性までは検証しません。ファイルの読み込みや JSON の解析に失敗した場合も例外になります。

## `collect(config)`

設定辞書を受け取り、勤怠表の各行を辞書にしたリストを返します。

1. `site` フォルダーを配信する HTTP サーバーを `127.0.0.1:8765` で起動します。
2. Playwright でヘッドレス Chromium を起動し、`site_url` を開きます。
3. `frames` に指定されたセレクターを順にたどり、対象の入れ子 iframe に移動します。
4. `table` のセレクターで表を探し、表示されるまで最大10秒待ちます。`rows` で行を取得し、各行の `td` の文字列の前後の空白を取り除きます。
5. セルを `columns` の名前と順番に対応付け、例えば `employee`、`date`、`clock_out` などをキーとする辞書にします。

セルと列名は `zip` で対応付けるため、数が違う場合、余ったものは無視されます。列の順序や数が変わった場合は設定やコードの確認が必要です。サーバーは取得中に例外が発生しても `finally` で停止します。ポートが使用中の場合や、画面・表を取得できない場合は例外になります。

## `check(records, rules)`

取得した行のリストとルールの辞書を受け取り、要確認事項のリストを返します。各結果には元の行の値に加え、`status`（「要確認」）と `reason`（理由）が入ります。

- `missing_clock_out` が有効で、`clock_out` が空または存在しない行を検出します。
- `overtime_must_not_start_before_scheduled_end` が有効で、`overtime_start` と `scheduled_end` の両方に値があり、残業開始が定時より前の行を検出します。

時刻は文字列として比較するため、サンプルのようなゼロ埋めされた `HH:MM` 形式を前提としています。日付をまたぐ時刻や異なる形式の扱いは検証していません。同じ行が両方のルールに該当すると結果は2件になります。

## `write_report(records, findings)`

取得した行と要確認事項を受け取り、HTML ファイルを作成して、そのパスを返します。`output` がなければ作成し、ファイル名には実行時刻を `YYYYMMDD_HHMMSS` 形式で付けます。

レポートには取得件数、要確認件数、社員・日付・判定・理由を表示します。要確認件数は該当行数ではなく、検出されたルール違反の件数です。要確認事項がない場合はその旨を表示します。表に埋め込む値は HTML エスケープします。同じ秒に複数回実行した場合は同じ名前になるため、先のファイルを上書きします。

## `main()`

`load_config()`、`collect()`、`check()`、`write_report()` を順に呼び出します。取得件数、要確認件数、レポートのパスを表示し、レポートをブラウザーで開くよう要求します。

途中で例外が発生すると、エラーを表示したうえで例外を再送出して処理を中断します。スクリプトを直接実行したときに `main()` が呼ばれます。
